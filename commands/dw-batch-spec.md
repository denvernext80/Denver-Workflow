vault 의 배치·크론 명세(정기 실행되는 작업을 적어 둔 문서)를 실제와 대조하거나 다시 훑는다.

인자 `$ARGUMENTS` 로 모드를 정한다:

- **인자 없음 → 드리프트 점검**(문서와 실제가 벌어졌는지 확인). 표면을 훑어 잡을 세고, vault
  `배치·크론 명세 — 전체 인덱스` 기록과 비교해 **차이만** 보고한다. 문서는 고치지 않는다.
- **`재추출`** → 전 표면을 다시 훑어 명세를 갱신하고, 변경 이력에 `재대조` 항목 1건을 남긴다.
- **`<그룹 이름>`** → 그 그룹 노트만 다시 훑어 갱신하고 인덱스 집계를 맞춘다.

## 절차

1. `dw_search("배치 크론 명세 전체 인덱스")` 로 인덱스를 찾는다.
   - **0건이면** 아직 명세가 없다 → 부트스트랩 절차(batch-cron-spec-bootstrap)를 안내하고,
     사용자가 동의하면 그 절차로 전 표면 탐색을 수행한다. 드리프트 점검은 건너뛴다.
2. **레포 선언분**을 훑는다 — CI 스케줄 트리거, 타이머 유닛, 예약 잡 정의, 앱 내장 스케줄러,
   크론을 설치하는 배포 스크립트, 하드코딩된 크론식. 표면별로 센다.
3. **호스트 설치분**은 접근 가능할 때만 확인한다. **접근을 얻으려고 보안 설정을 바꾸지 않는다** —
   못 보면 인덱스의 `미확인` 표기와 최종 확인일을 그대로 보고에 싣는다.
4. 모드에 따라 보고만 하거나(인자 없음), batch-cron-spec-update 절차로 갱신한다.

## 보고 형식

```
배치·크론 명세 점검 결과
- 명세 기록: 레포 선언 N개 / 호스트 설치 M개 (기준 <커밋 SHA>, YYYY-MM-DD 재대조)
- 실측: 레포 선언 N'개 / 호스트 설치 <확인함 M'개 | 미확인(최종 확인 YYYY-MM-DD)>
- 차이: +X 신규 / -Y 삭제 / Z건 스케줄 변경
- 비활성 잡: K개
```

차이가 0이고 호스트도 확인됐으면 "명세와 실제가 일치합니다" 한 줄로 끝낸다.
**호스트를 못 본 상태면 "일치합니다" 라고 쓰지 않는다** — "레포 선언분 일치, 호스트 설치분 미확인"
으로 정확히 쓴다.

## 주의

- 인자 없는 모드에서는 **절대 문서를 고치지 않는다.**
- **호스트 설치분의 불일치를 발견하면 임의로 명세를 맞추지 마라.** 누가 수동으로 심었거나
  지웠을 수 있다. 불일치 사실을 보고하고 사용자 판단을 받는다.
- 레포 선언분과 호스트 설치분을 **한 숫자로 합치지 않는다** — 확인 수준이 다르다.
- 비활성(꺼진) 잡을 "없음"으로 세지 않는다. 상태가 다를 뿐 존재하는 잡이다.
