---
vault 의 API 명세(현재 시스템의 모든 API 를 적어 둔 문서)를 코드와 대조하거나 다시 훑는다.

인자 `$ARGUMENTS` 로 모드를 정한다:

- **인자 없음 → 드리프트 점검**(전문용어: 문서와 실제가 벌어졌는지 확인). 코드를 훑어 엔드포인트
  총계를 세고, vault `API 명세 — 전체 인덱스` 에 적힌 총계·기준 커밋과 비교해 **차이만** 보고한다.
  문서는 고치지 않는다. 차이가 있으면 마지막에 "지금 갱신할까요?" 라고 묻는다.
- **`재추출`** → 전 도메인을 다시 훑어 명세를 갱신하고, 변경 이력에 `재대조` 항목 1건을 남긴다.
- **`<도메인 이름>`** → 그 도메인 노트만 다시 훑어 갱신하고, 인덱스의 해당 카운트를 맞춘다.

## 절차

1. `dw_search("API 명세 전체 인덱스")` 로 인덱스를 찾는다.
   - **0건이면** 아직 명세가 없다는 뜻이다 → 부트스트랩 절차(api-spec-bootstrap)를 안내하고,
     사용자가 동의하면 그 절차로 전수 스캔을 수행한다. 드리프트 점검은 건너뛴다.
2. 인덱스에 적힌 **라우트 정본**(URL 이 어떤 코드로 연결되는지 적힌 원본 파일) 경로와 기준 커밋을 읽는다.
3. 현재 코드에서 엔드포인트를 전수로 세고, 인덱스 기록과 비교한다.
4. 모드에 따라 보고만 하거나(인자 없음), api-spec-update 절차로 갱신한다(`재추출`·`<도메인>`).

## 보고 형식

사용자에게는 아래처럼 **숫자와 차이만** 간결히 보여준다:

```
API 명세 점검 결과
- 명세 기록: 총 N개 (기준 <커밋 SHA>, YYYY-MM-DD 재대조)
- 코드 실측: 총 M개 (현재 <커밋 SHA>)
- 차이: +X 신규 / -Y 삭제 / 도메인별 …
```

차이가 0이면 "명세와 코드가 일치합니다" 한 줄로 끝낸다.

## 주의

- 표본이 아니라 **전수**로 센다. 총계가 안 맞으면 점검의 의미가 없다.
- 인자 없는 모드에서는 **절대 문서를 고치지 않는다** — 점검과 갱신을 섞으면 사용자가 무엇이
  바뀌었는지 알 수 없다.
- 라우트 정본이 여러 레포에 나뉘어 있으면 레포마다 따로 점검하고 따로 보고한다.
