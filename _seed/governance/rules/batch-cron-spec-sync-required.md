title: 정기 실행(배치·크론)을 만들거나 바꿨으면 명세 갱신 + 변경 이력 없이 완료 금지
---
**언제·어디서·무엇이 도는지**가 달라지는 작업(정기 실행 신설·삭제, 스케줄식·타임존·실행 대상·
타임아웃·중복 정책·알림 변경, 잡을 끄는 것)은 아래 둘이 모두 끝나야 완료다:

1. vault `project/reference/` 의 해당 **그룹 상세 노트 갱신 + 전체 인덱스의 잡 수·표면별 집계 갱신**
   (레포 선언분과 호스트 설치분은 분리해 센다)
2. `배치·크론 명세 — 변경 이력` 노트에 **항목 1건 이상 prepend**
   (날짜·유형·잡 이름·스케줄·요약·근거 PR/커밋. 비활성·삭제는 **사유 필수**)

절차는 batch-cron-spec-update 를 따른다.

**검증자(`code-review`)가 보는 것**: PR diff 에 스케줄 트리거·타이머 유닛·예약 잡 정의·크론식·
크론을 설치하는 배포 스크립트 변경이 있는데 명세 갱신 근거가 PR 본문·세션 기록에 없으면
**Major 로 지적한다.**

**호스트 설치분의 불일치는 임의로 명세에 반영하지 않는다** — 명세와 호스트가 다르면 사용자에게
보고하고 판단을 받은 뒤 고친다(무단 변경이 조용히 정본이 되는 것을 막는다).

경계 — 이 규칙의 대상이 **아닌** 것: 잡이 실행하는 스크립트의 내부 로직만 바뀐 경우(스케줄과
실행 인터페이스가 그대로면 명세는 그대로다), 일회성 수동 실행, 아직 배포·설치되지 않은 선언
(명세는 **실제로 도는 현재 상태**만 담는다).

읽기 쪽 규율과 표면별 드리프트 판정은 [[batch-cron-spec-first]] 에 있다. 같은 계열의 API 표면
규칙은 [[api-spec-sync-required]] 다.
